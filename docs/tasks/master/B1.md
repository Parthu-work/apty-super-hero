# B1. Production Widget module and real-Client verification kit (Phase B; old ref P02)

*Skip and report if `docs/integrations/apty/reference-js/` is missing.* (It is missing at `dc27e2f`.)

**Why.** The Agent speaks the legacy verbs `get-service-worker-status`, `get-service-worker-logs`, `list-observed-resources`, `get-resource-body` (`apty/extension-network-inspector.ts`, `service-worker-diagnostics.ts`); failure codes are `not_allowlisted`, `bridge_missing`, `timeout`, `extension_not_found`, `invalid_extension_id`. The real Client's shared messaging library returns `true` for **every** message without replying to ones it does not own, so the module must register its own listener, answer only `apty-debug-agent:*` from allow-listed IDs, and return `false` otherwise. Apty's logger writes to `console.*`; its HTTP client resolves global `fetch` per request, so wrapping `fetch` captures its traffic (content-script requests are invisible to a service-worker recorder). The recorder must answer `list-observed-resources` and `get-resource-body` **synchronously** (the first `sendResponse` counts). `docs/integrations/apty/apty-widget-service-worker.reference.ts` and `docs/tasks/wp2-producer-handoff.md` are outdated.

**Do.**
1. Create `packages/apty-debug-contract/src/producer.ts` (exported so the Client team can `pnpm pack` and vendor it), self-contained apart from the contract's redaction, with minimal structural `chrome` types. Behaviour: listeners registered **synchronously at top level**; build-time `__APTY_DEBUG_BRIDGE__` gate and `__APTY_AGENT_IDS__` allow-list; wrap `console.*`, `error`, `unhandledrejection` and `fetch`; ring buffer in `chrome.storage.session` with a persisted `seq`, bucketed keys, immediate flush for errors and debounced otherwise, a byte cap, quota-error tolerance (drop oldest, count `dropped`); redact every entry at the source with `redactSensitiveText` (strict) and shrink `Reporting analytics event {…}` lines to `event_name`, `event_type`, `event_id`; bodies only for textual responses, redacted, configurable cap (default 1 MB) with a reason when skipped; serve the legacy verbs and contract-v1 `ping`, `get-logs`, `get-network`, `get-resource-body`.
2. A single-file IIFE `apty-debug-bridge.paste.js` for the runtime-paste fallback (`pnpm build:producer`), replacing the loose files.
3. Unit tests with a fake `chrome` (listener ordering, sender filtering, persistence across a simulated restart, quota errors, redaction, cursor paging, body cap).
4. e2e `tooling/e2e/apty-client-producer.e2e.test.mjs`: a fixture Client built from the **real module** proves logs, the request list, a 200 body and a 403 body. Terminate the Client's service worker using Chrome's documented approach for extension service workers under Puppeteer, prove the buffer survives and an Agent request wakes it; if infeasible say so, cover persistence in a unit test and put manual steps in the kit.
5. Docs: rewrite `docs/integrations/apty/README.md` (facts above, exact build flags, the Agent ID allow-list, security notes, what is logged and redacted); write `docs/integrations/apty/VERIFY_WITH_REAL_CLIENT.md`, a step-by-step manual script for the owner (install, set the Agent ID, reload, `chrome.runtime.id` checks, Settings → Apty Integration → Detect → Test connection, pull logs, request `segment.json`, stop the worker and repeat) with expected output per step.

**Tests.** Items 3 and 4. Do not claim the real-Client run passed; that is the owner's.

**Acceptance.** The module passes unit and fixture-Client e2e tests including worker termination and wake (or the limitation is stated); the real-Client verification script exists.
