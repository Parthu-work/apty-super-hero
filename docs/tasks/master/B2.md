# B2. Real-tenant validation tooling (athenaOne and Infor LN) (Phase B; old ref P03)

**Why.** DOM Health was built from redacted exports but never run on a live tenant (`docs/development/dom-health-architecture.md` "Known limitations"). Unverified: how Chrome reports a `javascript:` frame URL; whether athenaOne selected items use `fe_is-selected` or `fe_is-active`; whether Pendo renders in a frame; how the route probe reads on both apps. Heuristics marked unverified: `packages/dom-snapshot/src/health-state-signature.ts`, `health-dynamic.ts` (React `useId`), `health-privacy.ts` (free-text cut-off for `data-*`), `ignored-roots.ts` (matchers with `evidence: measured | repository | unverified | user`); other thresholds (click-first seed link count, same-URL share, unreadable-frame and structure-only confidence caps, collector budget) are in the architecture doc and code. A route probe exists (Settings → Troubleshooting → Developer tools: `packages/ui/src/components/settings/troubleshooting-card.tsx`, `apps/browser-extension/src/components/investigation/route-probe-panel.tsx`). Fixtures: `packages/dom-snapshot/src/__tests__/fixtures/erp/`. Runbook: `docs/development/dom-health-onboarding-runbook.md` (sections 0 to 9).

**Do.**
1. An **"Export validation bundle"** button in the DOM Health card and Developer tools. JSON containing: hostnames and URL templates (not full URLs), the frame tree with roles and responded or failed reasons, the route probe output, a DOM Health summary (counts, coverage, confidence caps, discovered states, overlay matches with evidence level), the thresholds in effect each flagged `unverified` or not, timings against the budget, extension and Chrome versions. **No** element text, input values, page titles, record numbers or cookies. Pass it through contract redaction (strict) and the existing capture-time privacy, with a "Review before sharing" preview.
2. One developer-only settings object (for example `domHealthThresholdOverrides`) that the unverified thresholds read from; defaults unchanged; active overrides listed in the bundle; nothing applied silently.
3. `tooling/scripts/bundle-to-fixture.mjs` turning a bundle into a redacted fixture skeleton plus test stub (runbook section 9).
4. `docs/development/real-tenant-validation.md`: use a test tenant or non-PHI data; screens (athena: frameset home, Patient Registration, a `pushState` route; LN: portal shell, then LN content after a menu click); checks (no "none of the frames responded"; application frame scored and navigation and status frames unscored; Pendo and chat launchers counted as overlays; same-URL screens found as separate states; audit within budget); what to send back.

**Tests.** Unit: a fixture with PHI-like strings (names, record numbers, emails, page titles) proves the bundle leaks none. e2e: export a bundle on the six application shapes in `dom-health-apps.e2e.test.mjs` and assert schema and privacy. **Out of scope:** tuning any threshold (that happens after the owner returns real bundles).

**Acceptance.** A validation bundle exports on the six app shapes with no text, values, titles or record numbers; the real-tenant protocol exists.
