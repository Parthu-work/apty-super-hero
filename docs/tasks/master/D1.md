# D1. Remove the skills feature (Phase D; old ref P14)

*Only if `SKILLS_DECISION = REMOVE`; otherwise write "kept by owner decision" in `REVIEW.md` and skip.* The owner did not edit the decision, so the default `KEEP` applies.

**Why.** Skills (a QuickJS sandbox inherited from the upstream project) are off by default and unrelated to debugging. They add about 4 MB of WebAssembly across four modules in `dist`, the `'wasm-unsafe-eval'` CSP allowance, an IndexedDB filesystem, a ZIP importer and a UI tab. Code: `packages/browser-runtime/src/skills/`, `packages/browser-runtime/src/vm/`, `skillTools` (6 tools, `skill.ts`), UI under `apps/browser-extension/src/components/skill/`, the Settings Skills tab, `skillExecutionEnabled`, the `aipex-skills-fs` IndexedDB, the `quickjs` dependency in `packages/browser-runtime/package.json` and `fflate` for the importer.

**Do.** Remove the runtime, tools, UI, settings, storage and dependencies. Remove `'wasm-unsafe-eval'` from the extension-page CSP if nothing else needs it and update `tooling/scripts/validate-manifest.mjs`. Add a small tested migration that deletes leftover skills IndexedDB data and settings keys on update. Run the full unit and e2e suites and `npm run lint:dependencies` (knip), removing anything newly unused. Report dist and extension size before and after. Update `PERMISSIONS.md`, `SECURITY_AUDIT.md`, `README.md`.

**Tests.** `audit:tools` and the manifest validator pass; an e2e check that Settings has no Skills tab and the side panel never offers a skill tool; the migration unit test.
