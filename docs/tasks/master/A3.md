# A3. Redaction mode control (Phase A; old ref P05)

**Why.** `RedactionMode = "strict" | "standard" | "off"` exists (`packages/apty-debug-contract/src/json-redact.ts`; `redactSensitiveText(text, mode = "strict")` in `redact.ts`), 16 non-test callers use the default, and `apty/dom-health-redaction.ts` has its own path. No setting or UI exists. Structural secrets (JWT, bearer, PEM, known token shapes) are redacted in every mode by design.

**Do.** Add `redactionMode` to `AppSettings` (`packages/agent-core/src/config/settings.ts`, default `"strict"`) and one accessor (for example `getRedactionMode()`) used by all callers in the side panel and service worker, cached and invalidated through `chrome.storage.onChanged`. Add a control to the Data-handling card: Strict (recommended), Standard, Off (development only), each with a plain description and a "Preview" showing a built-in sample (fake PII and secrets) before and after. **Off** requires a confirmation dialog and shows a persistent side-panel banner ("Redaction is OFF"); the dialog states structural secret redaction stays on. Include the active mode in the header of Copy and Download exports.

**Tests.** Unit: accessor, caching, invalidation, and a test that fails if any caller bypasses the accessor. e2e: fresh profile is strict; Standard changes the output for a fixture with a `username` and a page title; Off needs confirmation and shows the banner; the mode survives a reload; a JWT stays redacted in Off.

**Acceptance.** Redaction mode is selectable, previewable and honoured by every caller; Off needs confirmation and shows a banner.
