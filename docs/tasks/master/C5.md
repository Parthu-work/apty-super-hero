# C5. Widen the coverage gate (Phase C; old ref P09)

**Why.** Only `packages/apty-debug-contract` and `packages/browser-runtime` have `test:coverage` and thresholds (provider `v8`; `@vitest/coverage-v8` is a root dev dependency), and `browser-runtime` gates only six files (approval, trusted-sender, external-messaging, network-capture-session, session-snapshot, network-capture). `agent-core`, `dom-snapshot`, `ui`, `apps/browser-extension` and `apps/mcp-bridge` have none. The root `test:coverage` is `pnpm -r --if-present test:coverage`; CI runs it.

**Do.** Measure first: add `test:coverage` to each package and report the current numbers in `REVIEW.md` (wire `mcp-bridge`, outside the workspace, into the root flow and CI). Set each package-wide threshold **one point below the measured value** (a ratchet, not an invented target) and keep the strict per-file thresholds for the six critical files. Add targeted tests (not filler) for the lowest-covered security-critical or behaviour-critical files and list them; `packages/ui` has the weakest ratio. Document the rule: thresholds may only go up.

**Tests.** `npm run test:coverage` passes and fails if a file drops below its threshold (prove locally, do not commit).
