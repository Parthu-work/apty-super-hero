# B4. DOM Health: virtualized lists (Phase B; old ref P12)

**Why.** A virtualized list renders only visible rows, so a page can look healthier or emptier than it is. Coverage lives in `analysisCoverage` (`packages/dom-snapshot/src/health-types.ts`); the collector is `packages/dom-snapshot/src/health-collector.ts`.

**Do.** Detect signals: `aria-rowcount` / `aria-setsize` / `aria-colcount` larger than the rendered items; `role=grid|list|listbox|tree|table` whose scroll height far exceeds rendered content; `data-index` / `data-row-index` gaps; large explicit-height spacer elements. Report `virtualized: { containers, observedItems, declaredTotal }` and carry it into the report as **partial coverage with a reason**, never a clean pass, capping confidence when the unseen part is large. Optionally, behind the existing `discoveryMode` opt-in, a bounded time-boxed scroll sample (top, middle, bottom) that restores scroll position and never clicks. Add the signal to the Developer tools probe output.

**Tests.** Unit fixtures per signal and a negative case (a long non-virtualized list). e2e in `dom-health-apps.e2e.test.mjs`: a virtualized-list page reports correct counts and a coverage reason; scroll position is restored.
