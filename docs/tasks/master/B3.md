# B3. Structural summary for large JSON bodies (Phase B; old ref P11)

**Why.** For a 100 kB body the model gets an 8,000-character raw slice (15 of 206 items) and an `evidenceId`; `response.json` is empty for large bodies, so the model cannot learn the total or the shape without another call. `get_evidence_json(evidenceId, path, limit, offset)` is in `tools/extension-network.ts`.

**Do.** For JSON bodies larger than the preview, fill `response.json` with a summary under 1,500 characters: root type, array length, top-level keys (up to 30), for an array of objects the union of item keys with types, and how many items are in the preview. No values beyond what the preview already shows; apply the same redaction. Update the descriptions of `get_evidence_json` and the inspect tool: "read `json` first, then page with `get_evidence_json`".

**Tests.** Unit: arrays of objects, nested objects, mixed arrays, invalid JSON, empty array. Extend `wp1-acceptance.test.ts` with the 206-item fixture: the summary states 206 items and the item keys.
