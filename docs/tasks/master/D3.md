# D3. Release dry-run and browser smoke matrix (Phase D; old ref P16)

**Why.** `.github/workflows/release.yml` (tag trigger, version check, tests plus e2e, packaging, checksums, separate publish job) has never been exercised, and all tests run on Chromium 141, not on branded Chrome or Edge.

**Do.** Add a `workflow_dispatch` trigger with a `dry_run` input (default `true`) that runs every build, test, e2e, audit and packaging step and uploads artifacts but skips the publish job; keep least-privilege permissions and SHA-pinned actions. Add `tooling/scripts/release-dry-run.sh` running the same steps locally (using `tooling/scripts/check-release-version.mjs`, build, tests, e2e, package, checksums, checksum verification) with one summary line per step. Write `docs/release/SMOKE_TEST.md`: a manual matrix for branded Chrome stable and Edge (load unpacked, pinned ID check, first-run setup, one chat with a tool call, approval prompt, DOM Health on a multi-frame page, Apty handshake, readiness chips, purge) with a results table; state that branded Chrome cannot run the automated e2e. Add a dry-run step asserting the packaged manifest `key` yields the pinned Agent ID used by the harness (`AGENT_EXTENSION_ID`).

**Tests.** Run the local script and paste its output. The workflow change is checked by YAML lint and by reading it against the existing publish job; say plainly that you cannot run GitHub Actions.
